# vNext Agent multi-device and administrator operations

[简体中文](AGENT_OPERATIONS.zh-CN.md) · **English**

> [!IMPORTANT]
> These operations describe the unreleased v2.2.0/vNext Agent workflow. The
> stable v2.1.0 release continues to use one-shot pairing. Every Windows device
> must have its own SSH key and Agent credential.

## Roles

| Role | Synchronize own services | Generate ordinary-device code | List/revoke devices | Manage catalog/relays |
|---|---:|---:|---:|---:|
| `admin` | Yes | Yes | Yes, except itself | Yes |
| `device` | Yes | No | No | No |

The first administrator and every replacement administrator require a code
issued locally on Linux. A code generated by an administrator Windows device
always creates an ordinary `device`; it cannot promote a device to `admin`.

## Add an ordinary Windows device

Prepare Windows 11 x64, Tailscale in the same permitted Tailnet, Windows
OpenSSH Client, and the JK Bridge installer. Then:

1. On an enrolled administrator Windows computer, open **Device setup**, refresh
   Agent state, and select **Generate new device code**.
2. Transfer the displayed 10-minute, one-use code directly to the new computer.
   Do not place it in a note, screenshot, URL, or configuration file.
3. On the new computer, explicitly run **Discover Agent**, review/select the
   candidate, and choose **Use selected address**.
4. Enter a unique device label and the one-use code, then choose **Enroll and
   connect**.
5. Synchronize services and resolve any Windows-local port conflict. Windows
   listeners remain on `127.0.0.1`; Linux authorization still names only the
   exact Linux destination ports.

No Linux terminal is needed for this ordinary-device path after the Agent has
been prepared once.

## Add or replace an administrator

Administrator authority is not transferred by copying configuration, and an
ordinary device cannot be promoted in place. Enroll a new administrator first:

```bash
python3 ~/.local/lib/jkbridge/jkbridge_agent.py \
  --state-dir ~/.local/state/jkbridge-agent \
  recovery-code --role admin --ttl 900
```

Paste the code directly into the new Windows enrollment screen. The code is
valid once and Linux stores only its verifier. After the new administrator can
refresh the complete device list and connect:

1. stop/exit JK Bridge on the old administrator if immediate tunnel shutdown is
   required;
2. from the new administrator, refresh devices, select the old administrator,
   tick the explicit confirmation, and revoke it; and
3. remove the old computer from the Tailnet separately if it should lose all
   Tailnet access.

The Agent refuses removal of the final administrator. The Windows UI also
refuses self-revocation, so replacement is always "enroll new, verify, then
revoke old." Revocation blocks future Agent requests and new SSH connections;
it cannot terminate an SSH session that was already established.

If every administrator computer is lost, issue a new `admin` recovery code at
the Linux console, enroll a replacement, and revoke the lost records from that
new administrator.

## Remove an ordinary device

On an administrator Windows computer, refresh the Agent device list, select a
non-current device, review its stable identity, tick the confirmation, and
revoke it. Stop JK Bridge on that device first when immediate session cutoff is
needed. Do not remove keys by copying or editing another device's files.

## Safe migration and routine checks

- Export/import only the non-secret Service Profile when local service choices
  must move. Never copy a private key, Agent credential, authorization receipt,
  or the complete `config.json`.
- A Windows local port may differ from the Linux service port. The browser uses
  `http(s)://127.0.0.1:<Windows-local-port>/`; SSH authorization names the exact
  Linux port.
- Adding or changing a Linux destination requires an Agent catalog transaction
  or explicit one-shot re-pairing. A Windows-only port/path change does not.
- Agent availability controls enrollment and management. Existing authorized
  SSH tunnels remain a separate data plane.

Linux operators can inspect non-secret state without changing authorization:

```bash
~/.local/bin/jkbridge-agentctl status
python3 ~/.local/lib/jkbridge/jkbridge_agent.py \
  --state-dir ~/.local/state/jkbridge-agent status
```
